## 三态判定

1. **same**：相同已核准POI，或该内容版本已核准的POI→旧ID对应。显式地址/来源冲突转unknown；名称相似或同地址/近坐标本身不产生same。
2. **different**：原C2已核准具体餐厅，且可比的结构化地址成分明确不同。支持同街不同门牌、同门牌/院落不同楼栋、同楼/商场不同楼层或铺号，距离可为0。不同新旧POI本身不够证明不同实体。
3. **unknown**：可能相关但原/新地址不足，父级地址缺失不可比，同店址而无已确认POI对应，来源冲突或母点。保存具体原因与已核验材料，后续补证沿同一发布器重新确定性核验，不耗模型/attempt。

## 地址成分与比较顺序

复用NFKC、空白/标点规范及C2已有streetOf街道提取；不做全文字符串不等比较，不用模糊店名或距离判店。

| 成分 | 支持 | 不足时处理 |
| --- | --- | --- |
| 城市/行政区 | 北京/北京市、明确区名；作为父级范围 | 区名不足不能仅因此认定不同；同名街的范围不清待核 |
| 街道+门牌 | 路/街/大街/胡同/巷/条；数字门牌及甲乙前缀、明确院号 | 缺街或门牌不能只凭全文不同放行；地区不同需仍有完整具体地址 |
| 楼栋 | 明确N号楼/N栋；有街道门牌/院落或同名建筑/商场作共同父级 | 一方缺楼栋不能拿下一层差异当同一楼的差异 |
| 建筑/商场 | 原文明确大厦/中心/商场/SOHO等，仅作父级地址锚点 | 名称相似不等于同建筑，不按别称或附近位置猜对应 |
| 楼层 | 3层/3F/F3；B1/负一层/地下一层规范成同一层 | 一方缺楼层时，仅凭铺号相似/不同不能跨未知楼层推断 |
| 铺号/室号 | 明确101室/101铺、B1-117、3层302B等 | 导航说明、步行距离不当铺号；一方缺铺号时待核 |

比较从父级到子级：街道+门牌明确不同即different；相同父级下楼栋/楼层/铺号的首个明确差异可判different；未知父级不能跨层比较。明确地址相同仍不是same，必须POI或版本化对应。坐标只复核同POI/对应关系的明显冲突，不给different设置最小距离。POI原文/type/typecode继续否决文化/酒店/商场母点；没有类别信息不伪造证明。

识别范围之外、多个候选门牌、互相矛盾的组合、含不支持的地址别名或模糊范围均返回unknown。原店地址不够明确时，不能因为新地址更完整而补写旧地址。

## 同一16店基准的ATDD

每例独立内存bucket：原15冻结店+已核准曲廊院原始manifest/verification/图片，SHA原样保留；registry、probe为fixture，不触碰运行库或公开pointer。新增分店fixture必须经未改原C2 v1/v2，不能手填approved。

| 输入 | 预期 |
| --- | --- |
| 原前门店第二BV/博主+显式已核准对应 | 16店，一个门店点，多到访/视频，各博主自己的图文/视频 |
| 通州不同街/门牌/点位，无旧映射 | 17店；新实体可暂存/搜索 |

| 前门西大街4号，距2号<100米 | 17店；不因相邻待核 |
| 三里屯SOHO1号商场B1-118 vs B1-117，同坐标 | 17店；两实体/卡片可各自选中对应点 |
| 同楼不同楼层、同院不同楼栋 | 17店；有可比父级及C2具体餐厅证据 |
| 同址无对应、缺门牌/楼层/铺号、前缀相似、坏证据/来源冲突/母点 | stage拒绝或pending，原16店pointer不变，保留原因 |
