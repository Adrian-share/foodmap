## 从需求到真实地图验收

1. 解压任务附件，阅读 [开发要求](../../beijing-food-map/TASK.md) 和 [验收规格](../../beijing-food-map/验收用例.md)，保留 `samples.js` 的十家门店、GCJ-02 坐标、分店地址和探店来源。
2. 修改业务代码之前运行 `node --test acceptance.test.cjs`，原型基线 7/7 通过；再新增浏览器页面验收，完整得到 9/9 失败，证明原型尚未满足交互地图验收要求。
3. 接入高德 Web JS SDK 2.0、自定义编号图钉和信息窗；列表与地图共用同一份按 Haversine 直线距离排序的结果。搜索走服务端 Web 服务，JS 安全密钥由同源代理注入。
4. 通过固定搜索响应和模拟 SDK 验证起点、图钉、列表、地址、出处、请求逆序返回、歧义选择、清空与重试。数据与服务端 17/17、页面 9/9 通过。
5. 首轮没有 JS SDK 凭据，三条真实用例明确跳过，报告保留“待验证”。补齐凭据后进行真实高德联调，并修正自定义按钮的点击处理。
6. 真实信息窗可能遮住附近图钉，使用页面已有的「显示全部图钉」控件关闭详情后检查下一家；SDK 关闭窗口后会保留隐藏 DOM，因此测试验证用户可见的打开、关闭和切换行为。
7. 最终通过王府井、东坝、大钟寺三条真实用例：实时站点坐标与固定基准完全一致；全部四个点在视野内；九次门店点击的名称、地址、距离、来源链接和列表高亮均通过检查。
8. 人工查看三张最终截图，确认真实高德标识、道路、起点、三个图钉及列表同屏可见。凭据从未写入交付源码和归档。
