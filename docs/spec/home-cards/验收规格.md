# 首页图文卡与北京内容验收规格

## 内容盘点与入库

- 按三位指定 B 站 UID 逐一盘点，纳入实际到访门店位于北京市内的公开视频。记录 BV 号、UP 主、原视频链接、到访门店、视频片段和处理状态。
- 报告各账号的盘点入口、起止范围、停止位置及发现数、核对通过数、待核数、待补图数和排除数。范围受限时写明已盘点部分。
- 高德核对到具体分店、地址和 GCJ-02 点位。一个视频探多家店时各自关联到对应分店与片段。同一门店有多条探店视频时保留其关系。
- 门店与探店关系核对通过后进入首页搜索。仍缺截图的结果显示「截图待补」。带图文卡的新增门店验收使用一张与该店、该视频对应的真实截帧，并记录 BV 号、分 P 和时间点。

## 首页显示

桌面左侧为高德地图，右侧按距离排列卡片。每家店一张。卡片左侧为原视频截图，右侧按顺序显示地图编号、店名和直线距离，再显示分店地址、UP 主及一句可从视频核对的描述。短描述可以是原视频提到的菜品、观察或评价，有依据时才写，标明属于该 UP 主的探店内容。手机上图片和文字随布局换行，距离和截图都在结果卡片中可见。

卡片保留一个「查看探店详情」入口，打开站内详情。点击播放后用 B 站官方播放器。截图文件可随站点部署，视频始终由 B 站托管。页面不使用探味地图等第三方站点作为内容入口。 [B 站官方播放器](https://player.bilibili.com/)

## 通过条件

| 用例 | 操作与证据 | 通过条件 |
| --- | --- | --- |
| A01 三位 UP 主盘点 | 回读三位的盘点表和逐条记录。 | 三个账号各有盘点结果。每条已发现视频可追溯到原视频与处理结论，记录分店和截图待办。 |
| A02 新门店进入首页搜索 | 从原十家以外选一家已核对的北京分店。记录分店或 POI ID、BV 号和一个附近的地铁站或地标。部署前后用同一个地名走首页搜索。 | 接入前的结果中没有这家分店。接入后它出现在正常的距离排序和结果列表中，地图上有对应编号。搜索从现有数据读取新增门店，未给验收地名单独写固定结果。 |
| A03 新门店右侧卡片 | 在部署后的首页用 A02 的地名搜索，保留桌面截图和手机截图。 | 搜完即可在结果区看到该店的真实 B 站视频截图、直线距离、UP 主和一句简短描述。图实际加载成功。照片、视频、作者和分店一致，且可回查原视频的分 P 和时间点。 |
| A04 截图缺失与详情 | 分别检查一条无图或图片加载失败的结果，以及 A03 的站内详情。 | 无图结果提示截图待补，店名与距离仍可见。A03 的详情留在站内并展示正确 B 站原视频。 |
| A05 回归与复核 | 复跑原地图和搜索验收，重新导入同批数据并查看实际结果。 | 旧门店仍可被搜到，重复导入不增加重复点位或卡片。现有固定样本测试通过。线上结果按本次发布的数据重新排序。 |

验收记录附新增店名、分店 ID、BV 号、截图时间点、测试地名、预览地址、自动化结果和两种屏幕尺寸的截图。截图中的搜索框、地图点位和新增结果卡片应同屏可见，手机允许分段截图。A03 以正式卡片中实际加载的真实截帧为准。
