# 北京探店内容补齐与首页图文卡｜Multica 任务

在原 Multica 任务中继续，基于已验收的部署、高德地图和搜索实现。完成三位 UP 主的北京探店盘点，将核对通过的门店接入首页搜索，并在右侧显示对齐稿中的图文卡。完整的输入、展示与验收规则见《验收规格.md》。

| 基线 | 证据与范围 |
| --- | --- |
| 首页搜索 | 线上首页说明只在北京十家固定门店中取最近三家。附件《原十家样本.json》用于核对原始样本，执行时以改动前部署版本实际使用的门店 ID 为准。 [线上首页](https://shareworld-foodmap.yzxpg95.chatgpt.site/) |
| 视频批次 | 公开内容页显示正式收录 0 条。审核页显示三位 UP 主共九条候选，可作为首批线索。 [公开内容页](https://shareworld-foodmap.yzxpg95.chatgpt.site/content/) · [候选审核页](https://shareworld-foodmap.yzxpg95.chatgpt.site/content/?review=1) |
| 页面样式 | 《首页图文卡对齐稿.html》使用王府井现有地图和排序。图框用来对齐截图位置与大小。 |

## 开发顺序

1. 先按《首批来源.json》逐一盘点特厨隋坡、厨者王波、真探唐仁杰在 B 站公开且可访问的北京探店视频。九条候选是起点。记录每位的盘点范围和访问限制，逐条标记已收录、待核、待补图或排除，附原因。
2. 选出一个原十家之外、能核对分店且有真实截图的新门店。用这条记录写首页验收测试，记录接入前的失败结果，再继续整合。北京按实际到访分店的位置判断。
3. 将核对通过的门店接入首页实际使用的数据和排序逻辑。扩展门店与探店视频的关联，保留同一分店的多条视频关系，地图点位按分店去重。
4. 按对齐稿实现右侧图文卡，检查搜索响应里的门店、截图与视频能关联到同一次探店。沿用高德地图、直线距离口径和站内详情。视频通过 B 站官方播放器站内展示，截图可存到项目图片目录或部署的图片存储。
5. 在部署后的首页从新增门店附近搜索，按《验收规格.md》完成现场验收，附实际搜索结果与页面截图。

交付三位 UP 主的盘点表、接入记录、新店的原视频与截图来源、自动化测试和线上验收证据。
