# 每家店一张图片：实现与验证

已为十家固定样本各补充一张真实的原探店视频封面，并让 MCP 查询返回“图片＋门店名称＋直线距离＋探店出处”。
原 `samples.js` 中的店名、地址、坐标、视频、探店链接及距离排序均保持不变。

## 图片来源

使用原样本中每家店已有的 B 站视频，通过视频元数据接口核对视频 ID 并获取真实封面。
十张 JPEG 均下载并随代码保存于 `assets/images/`，查询时没有外网依赖。
每张图的门店、视频 ID、原始封面地址、下载地址、视频标题、来源、获取时间、文件大小和 SHA-256 均记录在 `assets/images/manifest.json`。
图片明确标记为“原探店视频封面”，内容可能包括菜品、博主和封面文字。

图片补充脚本是 `scripts/refresh-images.py`。刷新需要外网，已交付服务的运行及测试无需访问 B 站。

## 返回与展示

- 结构化结果：每家 `results[].image` 有可读取的图片地址、图片出处、说明及哈希；原门店字段完整保留。
- 图文：`cards_markdown` 包含三家店各一张 Markdown 图片、完整名称、公里制直线距离及探店、视频来源。
- 标准图片内容：MCP `content` 中实际返回三个 `type: "image"` 的 JPEG 内容块，而非只返回图片 URL。
- 图片读取：只读 `GET /images/<原视频ID>.jpg` 提供已登记资产，不接受任意文件路径。
- 图片地址默认使用本次 MCP 服务的主机和端口；经代理时可用 `PUBLIC_BASE_URL` 指定客户端可达根地址，代理需同时转发 `/mcp`、`/images/`。
- 缺位置或未知位置：不返回图片、不返回图文推荐，缺位置时仍先追问。

实现位置：`images.cjs`、`mcp-server.cjs`。现有原型七个输入文件保持逐字节一致。

## 测试先失败，再通过

新测试核对十家图片来源与哈希、三处起点的真实 MCP 图片响应、Markdown 图文、图片 GET 字节一致性及路径边界。

## 启动与复验

```bash
cd beijing-food-map-mcp
npm ci
npm start
```

默认 MCP 地址 `http://127.0.0.1:8767/mcp`。在另外一个终端运行测试：

```bash

npm run test:images
npm run test:codex
node scripts/preview-images.cjs
```
